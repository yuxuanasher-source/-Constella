# 游戏直播业务成本复杂规则交付功能设计

日期：2026-06-16

状态：MVP 已交付

## 实施同步

2026-06-16 已按 MVP 范围落地项目级复杂成本规则：Schema/RLS、套餐权益门控、复杂成本项目用量指标、规则版本、成本测算、导入/人工确认成本项、结算批次附件、角色安全导出、经营端入口和黄金路径回归。CPA/CPS/礼物/投流/供应商成本仍保持导入或人工确认边界，不进入全自动结算。

## 1. 设计目标

游戏直播项目的成本不是单一的主播时薪。实际交付里会同时出现 CPT、底薪、保底、CPA、CPS、礼物分成、任务奖金、扣罚、供应商成本、平台费用、投流费用、补播和人工调整。这个功能的目标，是把这些复杂成本从“线下表格和运营口径”收进系统，形成项目级规则配置、成本预估、结算明细、审批锁定和导出交付闭环。

本设计面向“复杂结算规则”商业能力，支持按项目开通：入门版/基础版可加购，专业版赠送 5 个项目额度，超额 99 元/项目/月，经营版和企业版默认开放。

## 2. 当前基础与新增边界

### 2.1 当前已具备的基础

当前系统已经有可复用的结算主干：

- 审核通过的直播报告进入待结算池。
- 支持生成应付主播批次和应收项目批次。
- 主播加入项目时冻结项目内结算规则快照。
- 自动计算 CPT、底薪、底薪 + CPT。
- CPA、CPS、礼物和人工调整作为人工明细进入结算单。
- CPS 可基于销售额和冻结的 CPS 比例计算人工金额。
- 结算批次支持锁定、重开、原因记录和高风险审计。
- 主播端只看安全的应付账单，不暴露供应商成本、毛利和内部财务字段。

### 2.2 本功能要新增的能力

“游戏直播业务成本复杂规则”不替代现有结算中心，而是在其上增加项目级成本规则层：

- 项目级复杂规则开关和额度计量。
- 游戏直播成本规则模板。
- 成本预估和报价测算。
- 直播后成本归集。
- 非主播成本明细，例如供应商服务费、投流、平台抽佣、样品/CDK、补播成本。
- 自动项、导入项、人工项的证据等级和审批链路。
- 成本和毛利看板。
- 对财务、供应商、客户交付的导出包。

## 3. 角色与使用场景

| 角色              | 主要诉求                                     |
| ----------------- | -------------------------------------------- |
| Owner / 负责人    | 控制项目毛利、审批高风险规则、锁定结算结果   |
| 运营经理          | 配置项目规则、确认主播成本、处理异常和补播   |
| 商务 / 项目经理   | 做报价测算、评估供应商成本、控制项目预算     |
| 财务              | 查看结算批次、复核成本、导出付款和对账材料   |
| 供应商 / 外部 MCN | 查看合作范围内的协作结算，不看内部毛利       |
| 主播              | 查看自己的应付明细，不看项目收入和供应商成本 |

## 4. 成本类型设计

### 4.1 主播劳务成本

| 成本类型   | 规则                           | 自动化等级      | 说明                                       |
| ---------- | ------------------------------ | --------------- | ------------------------------------------ |
| CPT        | `有效直播分钟 / 60 * 时薪`     | 自动            | 仅绿证据且系统时长可自动计算               |
| 底薪       | `周期底薪`                     | 自动            | 同一主播同一批次只应用一次                 |
| 底薪 + CPT | `周期底薪 + CPT`               | 自动            | 适合保底加时长计费项目                     |
| CPA        | `有效行为数 * 单价`            | 导入/人工       | 行为数来自客户或平台回传前，按人工明细处理 |
| CPS        | `销售额 * 分成比例`            | 导入/人工       | 分成比例可冻结，销售额需导入或人工确认     |
| 礼物分成   | `礼物收入 * 分成比例`          | 导入/人工       | 需平台礼物流水或人工确认                   |
| 任务奖金   | `达成条件后固定奖励或阶梯奖励` | 规则 + 人工复核 | 如连续播满、峰值在线、转化达标             |
| 扣罚       | `扣罚项金额` 或 `按比例扣减`   | 人工审批        | 如迟到、早退、未按脚本、鸽播、违规         |
| 补播成本   | `补播时长 * 成本规则`          | 自动/人工       | 与原任务关联，单独标记补播原因             |

### 4.2 项目交付成本

| 成本类型          | 规则                                       | 说明                                   |
| ----------------- | ------------------------------------------ | -------------------------------------- |
| 供应商服务费      | 固定金额、按项目比例、按主播数量、按场次   | 外部 MCN、招募服务商、内容服务商       |
| 协作分成          | `确认项目收入 * revenue_share_bps / 10000` | 跨 MCN 协作场景                        |
| 平台抽佣          | `收入或礼物流水 * 平台费率`                | 直播平台、支付渠道、服务商抽佣         |
| 投流成本          | 实际消耗或预算消耗                         | 用于毛利测算，不直接给主播             |
| 游戏资产成本      | 样品、CDK、游戏账号、道具、激活码          | 可按主播、场次或项目归集               |
| 内容制作成本      | 脚本、素材、剪辑、培训                     | 可归集为项目固定成本                   |
| 审核/人工服务成本 | 按场次、按小时、按报告数                   | 若平台方提供代审核服务，应进入履约成本 |
| 违约/赔付成本     | 固定金额或按合同比例                       | 主播或供应商异常产生                   |
| 税费/发票成本     | 税率、开票服务费、支付手续费               | 用于净收入和毛利口径                   |

## 5. 规则配置模型

### 5.1 项目级复杂规则开关

每个项目增加一个复杂成本规则状态：

| 字段                    | 说明                              |
| ----------------------- | --------------------------------- |
| `enabled`               | 是否启用复杂成本规则              |
| `enabledSource`         | 套餐内置、加购、销售特批          |
| `validFrom` / `validTo` | 开通有效期                        |
| `quotaProjectId`        | 消耗的复杂结算项目额度            |
| `billingMode`           | 套餐包含、99 元/项目/月、企业报价 |
| `enabledBy`             | 开通人                            |
| `enableReason`          | 开通原因                          |

未启用时，项目只能使用基础结算：CPT、底薪、底薪 + CPT、人工调整基础能力。启用后，才开放 CPA、CPS、礼物分成、供应商成本、毛利测算、规则模板、批量导入和复杂导出。

### 5.2 规则模板

规则模板用于减少每个项目重复配置。

| 模板            | 适用场景                       |
| --------------- | ------------------------------ |
| 标准 CPT 模板   | 游戏试玩、固定时长直播         |
| 保底 + 时长模板 | 大主播、稳定排期、品牌活动     |
| CPS 分成模板    | 游戏充值、道具销售、小游戏推广 |
| CPA 拉新模板    | 下载、注册、预约、首充         |
| 礼物分成模板    | 秀场化或互动玩法项目           |
| 供应商协作模板  | 外部 MCN 承接主播交付          |
| 投流毛利模板    | 项目需要同时管理投流和主播成本 |
| 补播扣罚模板    | 强 SLA、违约补播频繁的项目     |

### 5.3 规则优先级

结算时按以下顺序解析规则：

1. 项目内主播单独规则。
2. 主播加入项目时冻结的主播默认规则。
3. 项目默认规则。
4. 项目复杂成本规则模板。
5. 人工明细兜底。

规则一旦进入结算批次，应读取冻结快照，不应读取最新配置。这样可以避免后续改规则影响历史账单。

## 6. 计算规则

### 6.1 自动计算规则

自动计算仅用于证据强、规则确定的项目：

| 规则       | 自动计算条件                                            |
| ---------- | ------------------------------------------------------- |
| CPT        | 直播报告已审核通过，证据等级为 green，时长来源为 system |
| 底薪       | 同一主播同一项目同一批次未应用过底薪                    |
| 底薪 + CPT | 底薪条件 + CPT 条件同时满足                             |

不满足自动条件时，不应静默算钱，而是进入人工确认或人工明细。

### 6.2 导入计算规则

导入计算用于系统无法自证，但可以由外部数据源证明的成本：

| 规则     | 输入                         | 计算                             |
| -------- | ---------------------------- | -------------------------------- |
| CPS      | 销售额、冻结 CPS 比例        | `销售额 * cpsRateBps / 10000`    |
| CPA      | 有效行为数、单价             | `行为数 * 单价`                  |
| 礼物分成 | 礼物流水、分成比例、平台费率 | `礼物流水 * 分成比例 - 平台费用` |
| 投流     | 广告账户消耗                 | 直接作为项目成本                 |
| 平台抽佣 | 收入或流水、费率             | `基数 * 费率`                    |

导入数据必须保留来源、导入人、导入时间和原始文件引用。

### 6.3 人工明细规则

人工明细用于补差、异常、争议或线下确认：

| 人工项     | 规则                             |
| ---------- | -------------------------------- |
| 人工补款   | 必须填写金额、对象、原因和证据   |
| 人工扣减   | 必须填写金额、对象、原因和审批人 |
| 补播成本   | 必须关联原任务或原报告           |
| 违约赔付   | 必须关联合同或项目规则           |
| 供应商调整 | 必须限定在协作项目可见范围内     |

人工明细默认证据等级为 yellow 或 red。高风险金额需要 Owner 或运营经理审批。

## 7. 交付流程

### 7.1 售前/开项阶段

1. 商务选择游戏直播成本规则模板。
2. 输入主播数量、预计时长、预计 CPA/CPS、供应商费用、投流预算。
3. 系统生成成本预估、报价建议、毛利率和风险提示。
4. 若项目需要复杂规则，检查套餐权益或加购状态。
5. Owner 确认后，规则冻结为项目初始版本。

### 7.2 排期/执行阶段

1. 运营把主播加入项目。
2. 系统冻结每个主播的项目内结算快照。
3. 直播任务执行，直播报告收集系统时长、截图证据、人工申报信息。
4. 异常场次进入待复核。
5. 补播任务与原任务绑定，后续成本可追溯。

### 7.3 结算阶段

1. 审核通过的报告进入待结算池。
2. 系统按自动规则生成结算批次。
3. 运营导入 CPA、CPS、礼物、投流、平台费用等外部数据。
4. 系统生成成本明细和毛利测算。
5. 财务复核明细。
6. Owner 或运营经理锁定批次。
7. 系统生成导出包：主播付款表、供应商对账表、项目毛利表、异常明细表。

### 7.4 争议/重开阶段

1. 已锁定批次发现错误时，由 Owner 发起重开。
2. 必须填写重开原因。
3. 重开后新增调整项，不直接覆盖历史项。
4. 再次锁定后生成新版本导出包。

## 8. 页面与功能设计

### 8.1 项目设置 - 成本规则

功能：

- 开启/关闭复杂成本规则。
- 展示当前套餐权益和项目额度。
- 选择规则模板。
- 配置主播成本、供应商成本、平台费用、投流预算、税费规则。
- 保存规则版本。
- 预览对典型场次的结算影响。

关键提示：

- “规则变更只影响后续加入项目的主播或后续结算批次，不自动改历史账单。”
- “CPS、CPA、礼物分成需要导入或人工确认后进入结算。”

### 8.2 作战台 - 成本与毛利测算

功能：

- 项目收入、主播成本、供应商成本、投流成本、平台费、人工调整汇总。
- 毛利金额和毛利率。
- 保本报价。
- 建议最低报价。
- 低毛利、负毛利、高平台费、证据不足提醒。

### 8.3 结算中心 - 复杂成本明细

功能：

- 待结算池。
- 应付主播批次。
- 应收客户批次。
- 供应商协作结算批次。
- 成本明细列表。
- 人工新增 CPA、CPS、礼物、补差、扣罚、供应商费用。
- 批次锁定和重开。

### 8.4 导入中心

支持导入：

- CPA 行为数据。
- CPS 销售额。
- 礼物流水。
- 投流消耗。
- 平台抽佣。
- 供应商账单。
- 样品/CDK/账号费用。

导入后进入待确认状态，确认后才影响结算批次。

### 8.5 导出中心

导出包：

- 主播应付明细。
- 财务付款表。
- 供应商对账表。
- 客户交付表。
- 项目成本明细。
- 项目毛利复盘。
- 异常和人工调整审计表。

导出必须按角色做字段脱敏。主播和供应商不能看到内部毛利、其他主播金额、客户收入和非授权成本。

| 操作               | 权限                                           |

| 配置规则草稿       | owner, ops_manager                             |
| 审批规则生效       | owner                                          |

| 查看供应商协作结算 | partner，仅合作范围                            |

高风险规则：

- 人工金额超过阈值必须二次审批。
- 扣罚项必须填写原因和证据。
- 负毛利项目锁定前必须提示 Owner。
- 重开批次必须保留旧版本，不覆盖历史导出包。
- 供应商可见范围必须限定在协作项目和协作结算内。

## 12. 商业化规则

| 套餐   | 复杂规则开放                                 |
| ------ | -------------------------------------------- |
| 入门版 | 默认不开放，可按 99 元/项目/月加购           |
| 基础版 | 部分基础结算开放，复杂规则可加购             |
| 专业版 | 赠送 5 个复杂规则项目/月，超出 99 元/项目/月 |
| 经营版 | 默认开放                                     |
| 企业版 | 默认开放，可做专属规则和 API 对接            |

计费口径：

- 按自然月统计启用过复杂规则的项目。
- 项目开启后，当月消耗 1 个复杂规则项目额度。
- 项目关闭后不追溯返还当月额度。
- 专业版前 5 个项目消耗赠送额度，超出后按 99 元/项目/月。
- 销售特批必须写入结构化 quota override，不能只写备注。

## 13. MVP 范围

第一阶段建议只做能交付、能计费、能审计的闭环：

1. 项目级复杂规则开关和额度展示。
2. 规则模板：CPT、底薪 + CPT、CPS、CPA、供应商费用、人工调整。
3. 成本预览：收入、主播成本、供应商成本、投流、平台费、毛利。
4. 结算中心追加复杂成本项。
5. CPS 按销售额和冻结比例计算。
6. 导入 CPA/CPS/礼物/投流数据。
7. 批次锁定、重开和审计。
8. 导出主播付款表、供应商对账表、项目毛利表。

暂不做：

- 自动读取所有直播平台 GMV。
- 自动识别所有 CPA 行为。
- 自动扣罚。
- 复杂合同条款自然语言解析。
- 无限制自定义公式引擎。

## 15. 验收标准

- 项目可以单独启用复杂成本规则，并消耗套餐或加购额度。
- 专业版前 5 个复杂规则项目免费，超出项目能被识别为加购。
- 未开通复杂规则的项目不能配置 CPA、CPS、礼物、供应商成本和毛利增强字段。
- CPT、底薪、底薪 + CPT 继续沿用现有自动计算边界。
- CPA、CPS、礼物、投流、供应商费用可以通过导入或人工明细进入项目成本。
- CPS 可以按销售额和冻结比例计算金额。
- 人工明细必须有原因和证据等级。
- 成本规则变更不会改写历史结算批次。
- 批次锁定后不能直接编辑，重开必须由 Owner 操作并填写原因。
- 导出包按角色脱敏，主播和供应商看不到内部毛利。

## 16. 交付优先级

推荐交付顺序：

1. 复杂规则项目额度和权益门控。
2. 项目规则配置页。
3. 成本预览和毛利测算。
4. 结算中心复杂成本项。
5. CPA/CPS/礼物/投流导入。
6. 供应商协作成本归集。
7. 导出中心交付包。
8. 自动审核和作战台联动。

这套顺序可以先把 99 元/项目/月的商业能力跑通，再逐步提升自动化程度。
