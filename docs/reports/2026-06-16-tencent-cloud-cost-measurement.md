# 腾讯云部署成本测算底稿

日期：2026-06-16

## 1. 测算口径

本文用于把现有技术方案映射到腾讯云成本项，作为报价、套餐毛利和上线预算的第一版底稿。正式测算前，需要用腾讯云控制台价格计算器、商务折扣、模型厂商合同价和支付服务商费率替换本文中的假设。

建议同时维护两个口径：

| 口径               | 含义                                                                      | 适用场景                       |
| ------------------ | ------------------------------------------------------------------------- | ------------------------------ |
| 应用服务器上腾讯云 | Next.js 应用、API、Worker 放到腾讯云，Supabase 仍作为外部 BaaS 使用       | 快速上线、迁移成本低           |
| 全量腾讯云化       | 应用、数据库、Auth、私有文件、OCR、AI、日志、队列都按腾讯云或自建替代测算 | 私有化、国内合规、成本完全可控 |

如果只是“应用服务器上腾讯云”，数据库/Auth/Storage 仍应保留 Supabase 账单，不应混进腾讯云服务器成本里。
如果是“全量腾讯云化”，需要把 Supabase Auth、Postgres、Storage 的替代开发和运维成本也纳入。

## 2. 当前技术方案到腾讯云产品映射

| 当前能力       | 现有实现/依赖                                    | 腾讯云测算项                                              | 是否当前范围       |
| -------------- | ------------------------------------------------ | --------------------------------------------------------- | ------------------ |
| Web 应用与 API | Next.js App Router、route handlers、SSR          | CVM / TKE / 云函数 / CloudBase、系统盘、数据盘、公网流量  | 必算               |
| 多租户数据库   | Supabase Postgres、RLS、迁移、触发器、视图       | 云数据库 PostgreSQL：实例规格、存储、备份、审计、只读实例 | 全量腾讯云化时必算 |
| 登录与账号     | Supabase Auth、邮箱密码、短信 OTP、OAuth 预留    | 自建 Auth、短信、邮件、OAuth 服务、账号安全开发成本       | 全量腾讯云化时必算 |
| 私有文件       | 报数截图和导出包进入私有存储；录屏只保存外部链接 | COS：容量、读写请求、外网下载、CDN 回源、生命周期归档     | 必算               |
| OCR            | 腾讯云 OCR GeneralBasicOCR、OCR job runner       | OCR 按次、资源包、QPS 叠加包、失败重试                    | 必算               |
| AI 能力        | OpenAI / 混元 provider、AI invocation ledger     | OpenAI API 或腾讯混元/TokenHub，按 token 或调用量         | 必算               |
| 后台任务       | OCR runner、导出、异常扫描、自动审核             | CVM 常驻 worker / 云函数 / 消息队列 / Redis               | 必算               |
| 导出中心       | CSV、交付包、审计导出                            | 计算、COS 存储、下载流量、异步任务                        | 必算               |
| 站内通知       | notifications 表                                 | 数据库读写为主；外部渠道另算                              | 当前只算 DB 成本   |
| 外部通知       | 企业微信、飞书、短信、邮件                       | 短信、邮件、企业微信/飞书集成运维                         | 后续范围           |
| 商业化支付     | P5 只有套餐、权益、用量底座                      | 微信/支付宝/聚合支付手续费、退款、对账、发票              | P6 范围            |
| 日志监控       | 应用日志、审计日志、错误追踪                     | CLS 写入、索引、存储、告警、监控                          | 必算               |
| 安全合规       | RLS、RBAC、审计、私有文件                        | WAF、DDoS、高防、SSL、堡垒机、数据库审计                  | 按客户级别测算     |

## 3. 需要收集的业务输入

第一版不要先纠结机器规格，先把业务量拉清楚。

| 输入项     | 建议字段                                 | 说明                                             |
| ---------- | ---------------------------------------- | ------------------------------------------------ |
| 租户规模   | `org_count_by_plan`                      | 按入门版、基础版、专业版、经营版、企业版分别统计 |
| 员工席位   | `staff_seats`                            | 决定后台并发、账号/Auth 成本                     |
| 活跃主播   | `active_streamers`                       | 当前套餐核心变量                                 |
| 直播任务   | `live_tasks_per_day`                     | 决定报数、截图、OCR、审核量                      |
| OCR 调用   | `ocr_calls_per_month`                    | 建议按 `活跃主播 × 30 天 × 80% × 重试系数`       |
| OCR 重试   | `ocr_retry_rate`                         | 失败、人工重跑、重复上传都会放大成本             |
| AI 调用    | `ai_calls_per_month` 或 token            | 区分经营后台 AI 与主播端 AI                      |
| 截图体积   | `avg_report_screenshot_mb`               | 影响 COS 存储和上传/下载流量                     |
| 录屏链接   | `recording_link_count`                   | 当前只保存外部链接，不把视频文件计入 COS 容量    |
| 文件保留期 | `retention_days_by_type`                 | 截图、录屏、导出、日志应分开                     |
| 导出       | `export_jobs_per_month`、`avg_export_mb` | 影响计算、COS、下载                              |
| 流量       | `monthly_egress_gb`                      | 前端、图片、录屏、导出下载总外网流量             |
| 日志       | `app_log_gb_per_day`                     | CLS 写入、索引和存储                             |
| 短信       | `sms_count_per_month`                    | OTP、找回密码、通知类短信分开                    |
| 支付流水   | `subscription_gmv`、`addon_gmv`          | 用于支付手续费和退款成本                         |

## 4. 成本项与公式

### 4.1 应用计算

| 成本项         | 公式                                                    |
| -------------- | ------------------------------------------------------- |
| CVM / 容器实例 | `实例月价 × 实例数 + 系统盘 + 数据盘`                   |
| 弹性/按量计算  | `运行小时 × 小时单价`                                   |
| 云函数         | `调用次数费 + 资源使用费 + 外网出流量 + 预置并发闲置费` |
| 负载均衡       | `实例费 + 网络费 + LCU/性能容量费`                      |
| 公网           | `带宽包月费用` 或 `外网出流量 GB × 单价`                |

测算建议：早期用 2 台应用实例起步，一台跑 Web/API，一台跑 worker；正式生产至少考虑主备或自动拉起。

### 4.2 数据库与 Auth

| 成本项          | 公式                                            |
| --------------- | ----------------------------------------------- |
| PostgreSQL 实例 | `规格费用 + 存储空间费用 + 超额备份空间费用`    |
| 只读实例        | `只读实例规格 + 只读存储`                       |
| 数据库审计      | `审计实例/日志量/保存期`                        |
| Auth 替代       | `自建服务计算资源 + 短信 + 邮件 + 开发运维人力` |

注意：现有系统大量依赖 Postgres RLS、触发器、视图和 Supabase Auth。全量迁移时，不能只按数据库实例价格测算，还要算迁移、回归测试和账号体系替换成本。

### 4.3 COS 私有存储

| 成本项   | 公式                                                          |
| -------- | ------------------------------------------------------------- |
| 标准存储 | `月均存储 GB × 存储单价`                                      |
| 读写请求 | `PUT/POST/COPY 请求数 × 写请求单价 + GET 请求数 × 读请求单价` |
| 外网下载 | `外网下载 GB × 流量单价`                                      |
| CDN 回源 | `CDN 回源 GB × 回源单价`                                      |
| 生命周期 | `归档存储 GB × 单价 + 取回 GB × 单价`                         |

当前口径下录屏只保存外部链接，不把视频文件计入 COS 容量。现有文件大头会变成报数截图和导出包；建议截图压缩后上传，导出包设置短期保存和自动清理。如果未来改为自托管录屏，再单独增加视频容量、视频下载和生命周期归档成本。

### 4.4 OCR

| 成本项     | 公式                           |
| ---------- | ------------------------------ |
| OCR 调用   | `有效调用次数 × 单次价格`      |
| 重试成本   | `OCR 调用 × 重试率 × 单次价格` |
| 资源包     | `资源包价格 + 超额后付费`      |
| QPS 叠加包 | `购买 QPS × 日/月单价`         |

当前产品建议继续用强计量：额度耗尽后进入手动上传/手动填报，不允许后台静默透支。
已有成本模型可先用 `0.10 元/次` 做基准，`0.15 元/次` 做压力场景，正式报价前替换为实时公开价或商务价。

### 4.5 AI / 大模型

| 成本项          | 公式                                            |
| --------------- | ----------------------------------------------- |
| 按调用估算      | `AI 调用次数 × 单次平均成本`                    |
| 按 token 估算   | `输入 token × 输入单价 + 输出 token × 输出单价` |
| Shadow provider | `主调用成本 + shadow 调用成本 × shadow 比例`    |
| 工具调用        | `工具执行计算/外部 API 成本 + 日志记录成本`     |

现有环境支持 OpenAI 主 provider 和混元 shadow provider。若切换到腾讯混元，需要按模型路由重新估算 token 成本。

### 4.6 Worker、队列和缓存

| 成本项        | 公式                               |
| ------------- | ---------------------------------- |
| 常驻 worker   | `worker 实例月价 × 实例数`         |
| 云函数 worker | `调用次数 + 执行时长 + 出流量`     |
| 队列          | `消息写入/读取次数 + 消息堆积存储` |
| Redis         | `规格月价 + 备份/高可用`           |

OCR、导出、异常扫描、自动审核都属于异步任务。早期可用数据库队列表 + worker，规模增长后再引入消息队列和 Redis。

### 4.7 CDN、Edge 和下载

| 成本项      | 公式                                          |
| ----------- | --------------------------------------------- |
| CDN 下行    | `CDN 下行 GB × 流量单价` 或 `峰值带宽 × 单价` |
| HTTPS 请求  | `max(0, HTTPS 请求数 - 免费额度) × 单价`      |
| COS 回源    | `回源 GB × COS 回源单价`                      |
| 防盗链/安全 | `Edge/WAF/安全策略费用`                       |

导出包和截图如果被厂家或运营频繁下载，下载流量会明显增长。录屏链接如果直接跳转第三方播放，一般不进入腾讯云 CDN/COS 下载成本；如果未来改成代理播放或自托管视频，再单独增加视频下载口径。必须设置短期签名链接和防盗链。

### 4.8 日志、监控和审计

| 成本项   | 公式                            |
| -------- | ------------------------------- |
| 日志写入 | `压缩后写入 GB × 写入单价`      |
| 索引     | `索引 GB × 索引单价`            |
| 存储     | `日志存储 GB × 保存天数 × 单价` |
| 告警     | `告警策略/通知次数/监控增值项`  |
| 审计日志 | `数据库审计 + 应用审计表存储`   |

建议生产环境按日志类型分主题：应用错误、API 访问、OCR/AI provider、支付、审计。审计日志长保留，普通访问日志短保留。

### 4.9 支付、短信和邮件

| 成本项     | 公式                             |
| ---------- | -------------------------------- |
| 支付手续费 | `含税交易额 × 支付费率`          |
| 退款       | `退款笔数 × 退款服务费`          |
| 短信       | `提交成功短信条数 × 单条成本`    |
| 邮件       | `邮件量 × 邮件服务单价`          |
| 发票/对账  | `发票服务费 + 对账/财务运营成本` |

当前 P5 不是正式支付闭环，真实支付、发票、退款、对账、webhook 属于 P6。已有模型可先按支付手续费 `0.7%` 做粗算。

## 5. 第一版测算表结构

建议建一个 Excel/Sheet，至少包含以下工作表：

| Sheet               | 内容                                                    |
| ------------------- | ------------------------------------------------------- |
| `Assumptions`       | 单价、折扣、税率、支付费率、保留期、重试率              |
| `Usage_By_Plan`     | 各套餐组织数、席位、主播数、OCR/AI/导出/存储额度        |
| `Infra_Fixed`       | 应用、DB、worker、日志、安全、负载均衡等固定月成本      |
| `Tenant_Variable`   | 单租户 OCR、AI、COS、下载、短信、导出变量成本           |
| `Plan_Gross_Margin` | 每个套餐收入、成本、贡献利润、毛利率                    |
| `Addons`            | OCR 包、AI 包、存储包、主播席位加购                     |
| `Sensitivity`       | OCR 单价、重试率、录屏体积、下载流量、AI token 的敏感性 |

## 6. 套餐变量的现有默认值

现有成本模型已经有一组可用的初始假设：

| 项目             |                   默认假设 |
| ---------------- | -------------------------: |
| 支付手续费       |          含税交易额 × 0.7% |
| OCR 基准成本     |               0.10 元 / 次 |
| OCR 压力成本     |               0.15 元 / 次 |
| AI 粗算成本      |          0.05 元 / AI call |
| 存储粗算成本     |          0.15 元 / GB / 月 |
| 存储实际占用     |             套餐额度的 60% |
| OCR 月额度       | 活跃主播席位 × 30 天 × 80% |
| 主播端用量成本率 |         含税用量收入的 35% |

这些数值只适合第一版商业测算，不适合作为最终采购预算。

## 7. 成本控制建议

1. OCR 用量强计量，额度耗尽后手动填报，不做静默透支。
2. OCR job 使用 `imageBucket + imagePath`，服务端读取私有文件，不保存长久 base64。
3. 报数截图上传前压缩，录屏设置生命周期和过期归档。
4. AI 区分经营后台额度与主播端独立用量包，shadow provider 只在抽样流量开启。
5. 日志按主题设置保存期，普通访问日志短保留，审计/支付/安全日志长保留。
6. 导出文件使用短期签名链接，避免永久公开链接带来的下载流量失控。
7. 初期不要过早引入复杂队列；等 OCR/导出任务量稳定后再拆消息队列和 Redis。
8. 全量腾讯云化前，单独评估 Supabase Auth/Storage 替代开发成本，避免只看云产品账单低估总成本。
