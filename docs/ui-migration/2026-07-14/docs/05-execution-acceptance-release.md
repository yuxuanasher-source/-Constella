# 执行、验收与发布方案

## 1. PR 顺序

1. 基线：记录现有路由、性能、关键业务测试和原型截图。
2. 基础：设计 token、公共控件、Playwright 像素测试框架。
3. 壳层：服务端鉴权布局、侧栏、顶栏和移动端导航。
4. 数据解耦：按业务域从 `ops-reference.jsx` 抽离查询、动作和 DTO，不迁移旧 JSX。
5. 总览与项目：经营总览、项目列表、项目详情。
6. 供给与准入：主播资源池、选播准入。
7. 履约与报数：直播排班、报数审核。
8. 财务治理：结算、审计和导出。
9. 知识库：Markdown 阅读、类似文档工具的内容编辑和版本状态。
10. AI 作战台：会话、上下文、产物、来源和安全边界。
11. 设置：组织配置和剩余公共弹窗。
12. 收口：全量回归、灰度、监控和旧 UI 删除。

每个 PR 只迁移一个可验证边界，不同时修改数据库结构、API 合同和全局权限模型。

## 2. 每页完成定义

- 对应正式路由可直接刷新并恢复状态。
- 使用真实权限和数据合同，不依赖原型模拟数据。
- 默认、加载、空数据、错误、无权限和操作中状态齐全。
- 关键新增、编辑、审核、导出或锁定动作可用。
- 目标视口无溢出、遮挡、双滚动和布局跳动。
- 截图差异和性能预算达标。
- 旧页面仍可通过功能开关回退。

## 3. 必跑命令

```bash
pnpm lint
pnpm type-check
pnpm test:api-contracts
pnpm test:ui-smoke
pnpm test
pnpm build
```

根据业务域补充专项测试：

```bash
pnpm test:permissions
pnpm test:p3-governance
pnpm test:p4-flywheel
pnpm test:ai-system
```

## 4. 像素测试矩阵

每个页面至少包含：

- 桌面默认状态。
- 1280px 紧凑桌面状态。
- 390px 移动状态。
- 空数据或无匹配结果。
- API 错误状态。
- 主要弹窗或抽屉。
- 表格选中/编辑状态。

知识库额外覆盖阅读和 Markdown 编辑；AI 作战台额外覆盖新对话、历史对话和上下文隐藏/展开；结算额外覆盖锁定确认和金额异常。

## 5. 灰度发布

1. 使用 `NEXT_PUBLIC_OPS_UI_V2`、服务端配置或组织白名单控制新 UI。
2. 内部账号完成生产数据只读验证。
3. 按 10%、50%、100% 放量。
4. 至少保留一个发布周期的旧 UI 回滚能力。
5. 观察客户端异常、API 失败、路由加载时间和高风险动作成功率。
6. 所有路由稳定后删除旧字符串路由、旧重复样式和废弃组件。

## 6. 回滚条件

- 关键动作行为与旧页面不一致。
- 权限越界或错误隐藏。
- 金额、报数或结算状态显示错误。
- 新页面错误率明显高于旧页面。
- Web Vitals 或路由 JS 超过预算且影响操作。
- 像素问题导致主要控件无法使用。
