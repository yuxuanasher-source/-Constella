# 录屏交付复核工作台重塑设计

## 目标

把面向甲方的录屏分享页重塑为专业、紧凑、可连续处理的复核工作台。页面不再为每位主播重复铺设大卡片和播放器，而是通过左侧录屏明细队列选择条目，在右侧唯一播放器中完成查看与复核。

## 页面结构

### 项目信息栏

- 使用单行或紧凑双行信息栏展示项目名称、乙方/产品、分享状态、录屏总数和截止时间。
- 页面标题保持工作台尺度，不使用营销式大标题或说明性英雄区。
- 错误与成功消息继续位于项目信息栏下方，并使用礼貌的状态播报。

### 左侧：待审录屏明细

- 每条录屏只占一行，显示序号、主播名称、账号、版本、录屏状态、来源和当前复核决定。
- 点击整行选中录屏；当前行使用背景、边框和选中标记共同表达状态，颜色不是唯一提示。
- 列表内部可滚动，宽屏时与右侧面板分别停留在视口内。
- 首次加载默认选择第一条录屏；切换条目时保留各条目的未提交复核草稿。

### 右侧：播放器与复核

- 只渲染当前选中录屏的播放器，标题区显示主播、账号、版本和状态。
- 私有上传文件和可直接播放的视频 URL 使用原生 `video` 控件。
- B 站和 YouTube 页面 URL 转换为站内嵌入播放器；不把跳转第三方网站作为主要播放动作。
- 无法嵌入的普通网页链接显示清晰的不可内嵌提示，并保留原始链接作为兜底。
- 播放器下方呈现当前条目的复核决定、问题标签和备注。拒绝或需修改仍必须填写原因。

## 交互与数据

- `selectedRecordingSubmissionId` 只控制右侧当前条目，不改变后端 DTO 或提交协议。
- `drafts` 仍按录屏提交 ID 保存，提交时一次携带全部条目的录屏版本、决定、备注和问题标签。
- 分享页继续隐藏访问码、复核人姓名和联系方式字段；现有分享令牌、版本锁定与服务端校验保持不变。
- 分享数据刷新后优先保持原选中条目；若条目不存在则选择第一条。

## 响应式与可访问性

- 桌面宽屏使用约 `0.9fr / 1.1fr` 双栏；窄视口改为上下结构，列表在前、播放器在后。
- 行按钮支持键盘聚焦，使用 `aria-pressed` 表达选中状态。
- 表单保持显式标签、可见焦点和足够对比度；播放器区域维持稳定的 16:9 尺寸。

## 验收标准

1. 三条录屏只显示三行明细，页面初始只存在一个播放器。
2. 点击 B 站条目后，右侧切换为 `player.bilibili.com` 内嵌播放器。
3. 点击私有上传条目后，右侧切换为受分享令牌保护的原始录屏地址。
4. 切换条目前后，各条录屏的决定与备注草稿不丢失。
5. 提交载荷和拒绝原因校验与现有业务规则一致。
6. 桌面与移动视口无文本溢出、控件重叠或多播放器堆叠。
