# 星耀聊天自适应深度思考编排设计

日期：2026-07-19
状态：已确认，待实施计划

## 目标

将星耀聊天现有的“深度思考”模式从单次高推理强度模型调用，升级为可审计、可降级、可验证的自适应 Agent 编排流程。深度模式必须在 60 秒内完成，优先使用组织内部经营数据、知识库和用户附件；只有证据不足且问题确实需要外部事实时才联网检索。整个流程只读，只提出建议，不执行任何业务动作。

快速模式保持现状，不进入新编排器。

## 当前状态与差距

当前深度模式已经具备以下能力：

- 前端可在 `fast` 与 `deep` 之间切换。
- `deep` 会向 Provider 传递高推理强度配置，并使用独立回答提示词。
- OpenAI 与 DeepSeek Provider 已支持推理参数或推理模型选择。
- 聊天请求已经注入组织经营 grounding、知识库和附件。
- 会话协议已经具备回合状态、冻结上下文、SSE、重试、终态落库和调用账本。
- 现有 AI 输出体系已经具备事实溯源、人工确认和降级保护。

现有实现仍接近“单模型想得更久”，缺少 Agent 级的问题规划、证据充分性判断、按需联网、独立反方审查、修正和最终引用校验。

## 已确认的产品决策

- 作用范围：仅星耀聊天的“深度思考”模式。
- 延迟边界：用户总等待时间不超过 60 秒。
- 证据策略：内部数据优先，必要时联网检索。
- 执行边界：只读分析并提出建议，不自动创建、修改或发布业务数据。
- 过程反馈：显示稳定的阶段进度，不展示隐藏思维链或未经校验的中间结论。
- 实现路线：自适应深度推理编排，不采用单次增强提示词或完整多 Agent 辩论。

## 范围

### 包含

- 新增深度思考编排器及结构化阶段契约。
- 复用现有聊天 grounding、知识库、附件、Provider Gateway、Web Search Provider、调用账本和会话协议。
- 新增问题规划、证据整理、充分性判断、按需联网、分析、反方审查、修正和验证阶段。
- 新增深度思考阶段 SSE 事件与前端进度展示。
- 扩展冻结上下文，使技术重试复用已获得的计划和证据。
- 新增时间预算、失败降级、安全校验、观测指标和灰度开关。

### 不包含

- 不改变快速模式。
- 不自动执行任务、项目、主播、结算、财务或知识库写操作。
- 不向用户展示或持久化模型隐藏思维链。
- 不建设通用全产品 Agent Runtime。
- 不引入开放式多 Agent 争论或不受控的递归调用。
- 不新增独立数据库表；优先复用会话快照、消息元数据和 `ai_invocations`。

## 总体架构

`executeDashboardAiChat` 继续作为聊天入口。在完成认证、消息净化和基础上下文组装后按模式分流：

- `fast`：继续进入现有 `streamChatResponse` 路径。
- `deep` 且开关开启：进入 `DeepThinkingOrchestrator`。
- `deep` 且开关关闭：回退到现有单模型深度路径。

```text
用户深度问题
  -> 创建并锁定会话回合
  -> 规划问题与证据需求
  -> 整理内部经营数据、知识库和附件
  -> 判断证据是否充分
       -> 充分：直接分析
       -> 不足且需要外部事实：受限联网检索
  -> 形成结构化分析草案
  -> 独立反方审查
  -> 修正并生成最终答案
  -> 引用、安全和格式验证
  -> 提交回答与回合终态
```

建议在 `features/ai/deep-thinking/` 下建立独立边界。具体文件拆分由实施计划决定，但模块职责必须保持如下分离：

- `orchestrator`：阶段调度、截止时间、降级和聚合结果。
- `planner`：提取目标、子问题和证据需求，不直接下结论。
- `evidence`：统一内部证据、附件、知识库和网页结果。
- `assessor`：判断证据覆盖、矛盾和联网必要性。
- `analyst`：只依据证据形成结构化分析草案。
- `critic`：寻找无证据主张、反例、矛盾、遗漏风险和过度推断。
- `synthesizer`：根据审查结果修正草案。
- `validator`：执行引用、数字、只读边界和输出质量校验。
- `budget`：传播总截止时间和各阶段剩余预算。

这些单元通过结构化契约通信。模型输出必须先通过 schema 校验，不能把自由文本直接传给下一阶段作为可信事实。

## 会话与数据流

现有会话回合仍是状态真相，沿用：

```text
accepted -> grounding -> generating -> validating -> completed
                                             \-> failed
```

深度阶段是这个粗粒度状态机内的细粒度进度：

- `accepted / grounding`：规划、内部证据整理、充分性判断、可选联网。
- `generating`：分析草案、反方审查、修正。
- `validating`：引用、安全和最终格式校验。
- `completed / failed`：终态持久化后才发送终态事件。

`ConversationGatewayContext` 增加可选 `deepContext`。它只保存：

- 结构化问题计划。
- 内部证据 ID 与经净化的必要事实文本。
- 经净化的网页摘要、URL 和发布时间。
- 证据缺口与冲突。
- 已完成、跳过或降级的阶段。
- 审查判定和阶段耗时。

它不得保存模型隐藏思维文本。技术重试复用冻结的 `deepContext`，从第一个未完成阶段恢复；已经成功的联网检索不重复执行。若失败发生在 `deepContext` 完成冻结之前，重试复用已持久化的安全部分并补齐缺失阶段。

## 时间预算

路由继续保持 60 秒最大时长。编排器以请求级单调时钟计算 52 秒执行截止线，预留约 8 秒用于最终校验、数据库终态提交和网络传输。

| 阶段 | 建议上限 | 主要产物 |
|---|---:|---|
| 问题规划 | 6 秒 | 目标、子问题、证据需求 |
| 内部证据整理 | 10 秒 | 经营数据、知识库、附件证据包 |
| 证据充分性判断 | 3 秒 | 缺口、矛盾、是否需要联网 |
| 按需联网 | 8 秒 | 最多 2 个查询，每个最多 3 条结果 |
| 分析草案 | 10 秒 | 带证据引用的初步判断 |
| 反方审查 | 7 秒 | 反例、过度推断、遗漏风险 |
| 修正与验证 | 8 秒 | 最终答案与结构化元数据 |

这些是阶段上限，不是固定等待时间。未使用的预算向后传递；所有 Provider 与搜索调用接收由总截止时间裁剪后的超时值。

预算不足时按以下顺序降级：

1. 跳过尚未开始的联网检索，并记录外部证据缺口。
2. 将反方审查缩减为确定性规则校验。
3. 使用已有证据和草案生成保守结论。
4. 事实引用和安全边界校验不得跳过。

## 核心契约

```ts
type DeepPlan = {
  objective: string;
  subquestions: string[];
  requiredEvidence: string[];
};

type EvidenceSourceType =
  | "business_data"
  | "knowledge_base"
  | "attachment"
  | "web";

type EvidenceItem = {
  id: string;
  sourceType: EvidenceSourceType;
  statement: string;
  sourceId: string;
  url?: string;
  observedAt?: string;
};

type EvidenceAssessment = {
  coveredRequirements: string[];
  missingRequirements: string[];
  contradictions: string[];
  needsWebSearch: boolean;
  safeSearchQueries: string[];
};

type DeepReview = {
  verdict: "pass" | "revise" | "insufficient";
  unsupportedClaims: string[];
  contradictions: string[];
  missingEvidence: string[];
};

type DeepThinkingMeta = {
  status: "completed" | "degraded";
  webSearchUsed: boolean;
  reviewVerdict: "pass" | "revised" | "insufficient";
  evidence: EvidenceItem[];
  completedStages: DeepThinkingStage[];
  skippedStages: DeepThinkingStage[];
  elapsedMs: number;
};
```

分析草案与最终答案也必须是结构化 schema。关键主张携带 `evidenceRefs`，服务端验证引用后再渲染成用户可见 Markdown。深度模式不直接流出未验证的模型草稿；通过最终验证后，服务端才发送回答内容。

## 证据策略

证据优先级如下：

1. 组织经营数据。
2. 已审核知识库。
3. 用户本回合附件。
4. 外部网页。

内部系统是组织事实的权威来源。外部网页只用于市场背景、当前规则、竞品信息和交叉验证，不能覆盖系统内已记录的经营事实。

只有同时满足以下条件才允许联网：

- 计划明确需要当前市场、平台规则、政策、竞品或其他外部事实。
- 内部证据、知识库和附件不能覆盖该证据需求。
- 能生成不包含敏感信息的安全查询。
- Web Search Provider 已配置且剩余时间充足。

每个回合最多 2 个搜索查询，每个查询最多取 3 条结果。搜索词必须删除或替换：

- 主播和组织成员姓名。
- 内部项目 ID、账号 ID 和其他稳定标识符。
- 成本、报价、结算、回款和未公开经营指标。
- 私有知识库文本和附件原文。

只有明确标记为公开可搜索的产品、游戏、平台或行业名称可以保留。无法安全构造查询时跳过联网并记录证据缺口。

网页内容始终视为不可信数据：限制长度、净化内容、忽略网页中的模型指令，不允许网页内容触发工具或改变系统规则。网页来源必须保留标题、URL 和可用的发布时间。

## 阶段进度协议

`ConversationStreamEvent` 增加：

```ts
type DeepThinkingStage =
  | "planning"
  | "internal_retrieval"
  | "evidence_check"
  | "web_retrieval"
  | "drafting"
  | "reviewing"
  | "finalizing"
  | "validating";

type ReasoningStageEvent = {
  type: "reasoning.stage";
  conversationId: string;
  turnId: string;
  stage: DeepThinkingStage;
  status: "started" | "completed" | "skipped" | "degraded";
  elapsedMs: number;
};
```

`executeDashboardAiChat` 的执行选项增加阶段回调，`conversation-stream-adapter` 将其转换成正式会话 SSE。事件字段均为服务端枚举，不包含模型生成的过程文本。

前端按枚举映射为中文阶段状态。当前阶段可见，已完成阶段保留完成标记；回答完成后折叠成“深度分析已完成”。降级完成时显示“已基于现有证据完成”，具体缺口由最终答案说明。快速模式不展示阶段进度。

## 最终回答契约

最终回答稳定包含：

1. 结论。
2. 关键证据。
3. 不确定性与数据缺口。
4. 风险判断。
5. 建议与下一步。

可见证据编号使用：

- `[D1]`：组织经营数据。
- `[K1]`：知识库。
- `[A1]`：用户附件。
- `[W1]`：外部网页。

内部证据保留 `sourceTool + sourceId`，外部证据保留标题、URL 和发布时间。每条关键主张至少引用一条证据；引用不存在、类型不匹配或数字无法从被引证据追溯时，该主张不能进入最终答案。

所有建议使用建议语气，并继续遵守只读和人工确认边界。最终文本和 `DeepThinkingMeta` 一起写入助手消息元数据，便于重新打开会话和审计。

## 失败与恢复

| 故障 | 行为 |
|---|---|
| 规划模型失败 | 使用确定性问题分类和默认分析框架 |
| 部分内部数据不可用 | 继续分析并列出缺失模块 |
| 搜索未配置、超时或无结果 | 跳过联网，不影响内部分析 |
| 分析阶段超时 | 使用已有证据生成保守答案 |
| 反方审查失败 | 改用确定性事实和引用校验 |
| 最终 schema 或引用校验失败 | 剩余时间允许时修复一次，否则返回安全证据摘要 |
| 整体证据不足 | 不猜测，说明缺少的证据和补齐方式 |
| 终态持久化失败 | 不发送完成事件，客户端重新读取会话状态 |

客户端断线后，服务端仍应尽力在截止时间内推进并持久化终态。无法继续时必须把回合标记为可重试失败，不能提交半段回答。重新进入会话时读取服务端消息和回合状态，不依赖客户端缓存恢复。

## 安全与审计

- 所有业务读取继续使用当前认证上下文和组织范围，组织 ID 不接受模型或客户端输入。
- 编排器只能调用只读数据源和 `WebSearchProvider`，不注册写工具。
- 外部搜索前执行查询脱敏，测试必须证明敏感字段不会离开服务端。
- 网页文本不能覆盖系统指令、权限、证据优先级或只读边界。
- 每次模型调用继续写入 `ai_invocations`，metadata 记录 `turnId`、深度阶段、Provider、耗时和降级原因。
- 回合元数据只保存结构化摘要和引用，不保存隐藏思维链、Provider 原始响应或内部堆栈。
- 所有建议继续要求人工确认，尤其不得改变结算、财务、证据、审核和项目状态。

## 观测指标

新增以下聚合指标：

```text
deep_turn_completion_rate
deep_turn_degraded_rate
deep_stage_duration_ms
deep_web_search_trigger_rate
deep_evidence_count
deep_citation_rejection_count
deep_total_latency_ms
deep_prompt_and_completion_tokens
```

指标只记录状态、数量、Provider、阶段和耗时，不记录用户问题、网页正文、附件正文或敏感经营数据。整体调用成本由同一 `turnId` 下的阶段调用聚合。

## 测试策略

### 单元测试

- 总截止时间、阶段预算裁剪和预算不足降级。
- 证据优先级、去重、缺口和矛盾判断。
- 联网触发与不触发规则。
- 搜索查询脱敏和无法安全搜索时的跳过行为。
- Planner、Analyst、Critic 和最终答案 schema 校验。
- 引用存在性、数字可追溯和无证据主张过滤。
- 阶段状态机及 `started / completed / skipped / degraded` 事件。
- 每类失败路径的确定性回退。

### 集成测试

- 深度回合完整 SSE 顺序和终态落库。
- 内部证据充分时不调用 Web Search Provider。
- 外部证据确有必要时最多执行 2 个安全查询。
- 搜索失败后仍生成带缺口说明的答案。
- Provider 超时、schema 失败、审查失败和修复一次路径。
- 技术重试复用冻结证据，不重复联网。
- 客户端断线后回合最终状态可重新读取。
- 深度消息元数据可以通过会话读取接口恢复。
- 快速模式继续走原路径，响应契约和延迟无回归。

### 安全测试

- 低权限角色和跨组织请求零数据泄露。
- 主播姓名、内部 ID、金额和知识库原文不会进入联网查询。
- 网页提示注入不能改变系统规则或触发动作。
- 所有 Agent 工具保持只读。
- 最终建议不包含自动执行语义或可执行动作字段。

### 黄金用例

覆盖经营总览、ROI 归因、主播表现、风险诊断、方案比较和外部市场问题。比较现有深度路径与新编排路径的事实正确性、证据覆盖、风险识别、建议可执行性和总体偏好。

## 验收标准

- 所有数字和关键事实的有效引用覆盖率为 100%。
- 无来源的内部事实数量为 0。
- 内部证据充分时联网调用率为 0。
- 明确需要当前外部信息且内部证据不足时能够触发联网。
- 每回合最多 2 个搜索查询，每个最多 3 条结果。
- 所有建议保持只读并要求人工确认。
- 用户总等待时间不超过 60 秒，服务端编排截止线为 52 秒。
- 任一非关键阶段失败时，返回明确标记的降级答案。
- 没有足够证据时明确拒绝猜测。
- 快速模式行为、接口和现有测试保持不变。
- 会话、回合、阶段调用、证据和最终消息能够通过 ID 审计关联。

## 灰度与回退

使用服务端开关 `AI_DEEP_ORCHESTRATION_ENABLED` 控制新编排器。关闭时，`deep` 回到现有单模型深度路径，不需要重新构建前端。

上线顺序：

1. 本地和 CI 使用确定性 Provider 覆盖所有状态与降级路径。
2. 对指定内部组织启用，观察延迟、降级率、引用拒绝率、联网率和成本。
3. 对复杂黄金问题执行人工盲评；满足事实与引用硬门槛后扩大范围。
4. 全量启用后继续保留旧深度路径作为紧急回退。
5. 快速模式始终不进入新编排器。

## 实施约束

- 当前工作区存在与本设计无关的修改，实施时必须保留并避免混入提交。
- 优先复用现有 Provider、Gateway、Web Search、Conversation 和 Invocation Ledger，不建立第二套基础设施。
- 新编排逻辑必须可以使用测试 Provider、假时钟和注入式搜索适配器做确定性测试。
- 任何实际 Provider 能力差异必须由适配器吸收，业务编排器不直接拼接供应商专属请求。
