# 经营舱功能闭环设计

## 目标

把经营舱从“核心链路可演示、部分按钮仍是 UI”推进到“主要模块入口都有明确业务结果”。本轮重点不扩张到真实支付、生产发布、外部凭证或破坏性数据操作；这些属于硬闸口，需要单独确认。

## 当前判断

经营舱已有可用底座：

- M1 项目：项目列表读取、创建草稿、发布招募。
- M3 选播：报名队列读取、录屏审核、二次确认加入。
- M4 排班：创建任务、批量排班、取消任务。
- M5 报数：单条审核与刷新。
- M6 结算：创建批次、人工调整、锁定、重开。
- M7/M8/M9/M10/M11：审计、导出、通知、战情室、计费状态已有部分 API 或 UI。

主要缺口集中在三类：

- 已有 API 但 UI 没接：主播创建、风险更新、项目邀请、治理导出、通知跳转、战情室次级按钮。
- 有 UI 和本地状态但没有真实业务结果：筛选、查看详情、编辑/保存草稿、批量操作、导出按钮。
- 需要新后端 slice 才能完成：组织成员管理、正式组织设置、真实套餐变更、真实账单/支付。

## 推进原则

1. 先接已有 API，少造新后端。
2. 没有后端 slice 的入口不再假装可执行，要么变成真实本地筛选/导航，要么变成清楚的只读状态。
3. 每个阶段都必须有测试覆盖，提交后自动进入下一阶段。
4. 不做真实支付、生产部署、破坏性数据库重置、外部服务凭证接入。

## 阶段设计

### 阶段 1：M2 主播资源池

把主播池从“能看列表”推进到“能维护资源池核心状态”。

- 搜索、品类、来源、合作状态、风险筛选改为真实本地过滤。
- “新增主播档案”打开正式表单，提交 `/api/streamers`。
- “设置风险”打开风险表单，提交 `/api/streamers/:id/risk`。
- “邀请加入项目”使用当前可见项目选择，提交 `/api/projects/:projectId/invitations`。
- “导出主播表”走 `/api/exports` 的受控导出。
- 批量导入先明确为未接入导入后端，不再表现为可完成动作。

### 阶段 2：M1 项目管理

把项目管理二级入口接到已有中心或已有 API。

- 项目列表搜索和厂商/负责人/时间筛选真实生效。
- “导出项目表”走受控导出。
- “厂家交付包”走 M8 导出中心能力或直接调用 `/api/exports`。
- “新建排班”跳转到 M4 并带入项目上下文。
- 项目详情的录屏、排班、报数、结算、审计标签跳转到对应模块，避免空白标签页。
- 项目设置在本轮只保留可发布/基础信息已有能力，不新增完整设置后台。

### 阶段 3：M4 排班与任务

把排班页的次级操作变成可执行工作流。

- 项目、主播、状态筛选真实生效。
- “查看报数”跳转 M5。
- “预览主播端”跳转/打开主播任务入口。
- “扫描历史”调用 `/api/anomalies/scan`。
- 异常任务的“查看任务”定位任务，“标记处理”用可追踪状态或说明降级，“联系主播”明确为通知/待办入口。
- Excel 导入没有导入后端，本轮改成不可执行说明或后续入口。

### 阶段 4：M5/M6 审核结算增强

把报数和结算的批量、导出、表单体验补齐到可验收。

- 报数搜索、日期、项目筛选真实生效。
- “批量审核通过”对当前筛选待审列表逐条调用审核 API。
- “导出报数明细”走受控导出。
- 审核 payload 使用“计入任务结果”复选框。
- 结算创建批次和人工调整从 `prompt` 改为正式表单。
- “批次导出 / 导出 PDF”走受控导出或明确为 CSV 导出，不伪装 PDF。
- “查看审计”跳转 M7 并带上下文。

### 阶段 5：M0/M9/M10/M11 收尾

处理剩余经营舱入口，明确哪些是本轮可完成，哪些需要新后台。

- 顶部通知铃铛打开 M9。
- M10 次级按钮改为真实导航、导出或只读状态。
- M11 只读计费状态保留，套餐变更/支付入口标记为硬闸口。
- M0 组织成员管理需要新后端 slice；本轮先把成员列表接真实组织成员读取能力，如无法在现有迁移中低风险完成，则明确只读。
- 更新路由契约状态，避免仍标 `stub` 的模块误导验收。

## 测试策略

- 每阶段先写失败测试，再实现。
- UI 行为用 `components/reference-ui/ops-reference.test.jsx` 覆盖。
- API DTO 或纯函数用对应 `features/*/*.test.ts` 覆盖。
- 每阶段至少运行对应 focused tests、`pnpm type-check`、相关 smoke。
- 最终运行 `pnpm test`、`pnpm type-check`、`pnpm test:ui-smoke`、`pnpm test:manual-acceptance-smoke`。

## 硬闸口

以下事项不自动推进：

- 真实支付、套餐购买、发票、外部支付渠道。
- 生产部署、推送远端、创建 PR。
- 破坏性数据库重置或删除真实数据。
- 新外部服务凭证、短信/邮件真实发送。
- 大范围组织账号/认证体系重构。
