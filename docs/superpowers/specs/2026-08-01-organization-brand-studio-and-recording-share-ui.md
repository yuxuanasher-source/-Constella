# 组织品牌中心与录屏分享界面设计规格

> 状态：已完成产品与视觉确认，等待实施计划。
>
> 日期：2026-08-01
>
> 适用范围：经营 Web 主界面中的组织品牌层、组织品牌中心、内部录屏分享管理视图、公开录屏复核页。

## 1. 背景

经营舱服务游戏直播 MCN、直播工作室和主播运营团队。产品已经支持组织名称、LOGO 字标、品牌名和品牌副标，但这些能力仍停留在侧栏局部展示：

- `organizations.branding` 当前只保存 `logoText`、`brandName` 和 `brandTagline`；
- 组织设置抽屉可以修改上述字段，但缺少图片 LOGO、品牌主色、实时预览、草稿和发布语义；
- 内部主界面已经读取组织品牌信息，公开录屏复核 DTO 与页面却没有组织品牌或组织联系名片；
- 公开录屏页使用项目标题和复核信息组织页面，中间播放器区域在未播放时呈现为面积过大的深色块，压过了组织品牌与任务信息；
- 内部和外部界面虽然都能完成业务任务，但没有形成可解释、可追溯、稳定的同源品牌体验。

本次设计将“用户自己的组织品牌”提升为产品中的一等身份层，同时保持经营工具的可信、克制和高效，不把后台改造成营销落地页。

## 2. 已确认决策

1. 品牌主体采用“组织／MCN 主品牌，项目作为子品牌”。
2. 视觉方向采用“品牌工作台”：品牌清晰可见，但不压过业务任务。
3. 第一版采用“专业品牌套件”，包含图片 LOGO、品牌主色、品牌名、品牌口号、分享署名和组织联系名片。
4. 品牌色接管 LOGO、当前导航、主要操作和分享抬头；成功、预警、风险等业务状态色保持固定。
5. 品牌编辑使用组织模块下的独立“品牌中心”，不继续挤在组织设置抽屉中，也不侵入日常业务页面做就地编辑。
6. 对外联系方式由分享创建者从组织联系名片中明确选择，也可以选择不展示。
7. 内部录屏分享管理视图与公开录屏复核页必须使用同一份组织、项目和分享信息；两者不是只有颜色相同的两套页面。
8. 播放区域使用浅色媒体工作区。待播放和加载阶段显示组织品牌封面；开始播放后才展示真实视频画面。
9. 不使用未经定义的“已认证”宣称。第一版只使用“组织官方分享”，其含义是链接由当前组织内有权限的成员创建。

## 3. 目标

### 3.1 用户目标

- 组织成员进入经营 Web 后能清楚感知“这是我们组织的工作台”。
- 组织负责人可以安全地配置、预览和发布品牌，而不是修改后立即影响所有成员与链接。
- 厂家或品牌方打开录屏分享链接时，能第一眼确认分享来自哪个组织、对应哪个项目、由谁对接。
- 内外页面的关键项目与复核信息一致，减少接收者对链接可信度和资料归属的疑问。
- 品牌装修不降低业务状态、风险、金额和下一步动作的辨识效率。

### 3.2 产品目标

- 建立可复用的组织品牌数据契约，为其他外部分享页面提供统一基础。
- 将品牌发布、分享快照、联系名片选择和紧急移除纳入权限与审计体系。
- 在不暴露内部字段的前提下，提高公开分享页的专业度与组织识别度。
- 让品牌色和 LOGO 在无效、缺失或加载失败时有确定性降级路径。

## 4. 非目标

第一版不包含：

- 自定义域名；
- 多套分享模板；
- 按项目独立配置整套品牌主题；
- 任意字体上传；
- SVG LOGO；
- 视频内容级动态水印或防录屏能力；
- 自动声称第三方认证、资质认证或平台背书；
- 让品牌色替换成功、预警、风险和信息状态色；
- 对定价页、登录页、主播移动端和主播桌面端做全面白标化。

## 5. 信息架构

### 5.1 品牌中心

品牌中心是“组织与权限”的独立二级页面，并提供可直接访问的稳定路由。页面分为两列：

- 左侧：品牌资料、品牌主色、组织联系名片、草稿状态和发布操作；
- 右侧：内部工作台与公开录屏分享页实时预览，可在两种预览间切换。

只有组织负责人可以编辑和发布。其他有组织模块访问权限的成员只能查看当前已发布版本和发布时间。

品牌中心必须明确区分：

- 当前线上版本；
- 未发布草稿；
- 上次发布者与发布时间；
- 发布后影响的新页面与新分享；
- 已有分享为何保持原快照。

### 5.2 主界面品牌层

主界面保留现有高密度任务结构，只调整品牌身份层：

- 侧栏第一位展示图片 LOGO 或字标回退、品牌名和品牌口号；
- 当前导航、主要操作按钮和可见焦点使用经过对比度校正的品牌操作色；
- 组织名称与当前角色仍作为工作上下文展示；
- “品牌中心”作为组织模块中的明确入口；
- “经营舱”退到低优先级的技术服务署名，不与组织品牌争夺第一视线；
- 不增加大面积营销英雄区、装饰性指标卡或页面加载编排动画。

### 5.3 内部录屏分享管理视图

内部视图是公开分享的权威配置来源。它必须展示：

- 组织品牌预览；
- 项目名称；
- 分享标题与用途；
- 模式、轮次、截止时间与进度；
- 录屏清单及排序；
- 选中的组织联系名片或“不展示”；
- 访问控制、链接状态、撤销、源文件健康、播放问题和审计入口；
- 外部页面预览。

内部专属信息不得进入公开 DTO，包括访问令牌、访问码哈希、内部风险、成本金额、私有存储路径、源健康诊断细节和完整审计记录。

### 5.4 公开录屏复核页

公开页面按以下层级组织：

1. 组织品牌抬头：LOGO、品牌名、品牌口号、“组织官方分享”和可选联系入口；
2. 项目与分享上下文：分享标题、项目名称、用途、轮次、模式、进度和截止时间；
3. 安全说明：链接用途、操作会被记录、技术服务署名；
4. 复核工作区：录屏清单、媒体播放、逐条复核；
5. 可选组织联系名片；
6. 提交汇总与回执。

公开页面不展示未经定义的认证标记，也不根据品牌色改变审核结论和风险状态的语义颜色。

## 6. 内外同源信息契约

### 6.1 必须一致

- 组织品牌快照；
- 项目 ID 对应的项目名称和项目代码；
- 分享标题与用途；
- 分享模式、轮次、截止时间；
- 录屏项、录屏版本、顺序和主播展示名；
- 选中的组织联系名片快照；
- 分享状态和最新提交回执。

### 6.2 仅内部可见

- 原始 token、token 哈希和访问码哈希；
- 私有存储路径；
- 源文件健康诊断与内部播放问题详情；
- 组织内部风险、金额、成本、内部备注；
- 创建、撤销、访问和数据变更的完整审计明细；
- 组织联系名片的未公开字段。

### 6.3 仅外部产生

- 外部逐条评审草稿；
- 外部评审理由和备注；
- 最终提交回执。

这些数据提交后同步回内部分享管理视图，但不会反向改写分享创建时的品牌与联系名片快照。

## 7. 品牌数据模型

### 7.1 当前发布品牌

继续使用 `organizations.branding` 作为当前已发布品牌的快速读取镜像，兼容现有鉴权上下文和侧栏。扩展后的规范字段为：

```ts
type OrganizationBranding = {
  schemaVersion: 1;
  version: number;
  logoText?: string;
  logoStoragePath?: string;
  brandName?: string;
  brandTagline?: string;
  primaryColor?: string;
  publishedAt?: string;
};
```

`primaryColor` 保存规范化后的十六进制种子色。界面实际使用的操作色、浅色底和焦点色由确定性函数生成，不把一整套自由颜色直接写入数据库。

### 7.2 品牌版本

新增组织品牌版本记录，用于：

- 保存草稿；
- 乐观并发控制；
- 预览和发布；
- 保留发布历史；
- 审计发布者、发布时间和变更字段。

每个组织最多有一个活动草稿和一个当前发布版本。发布操作必须在一个事务内：

1. 校验草稿版本；
2. 归档上一发布版本；
3. 发布当前版本；
4. 更新 `organizations.branding` 镜像；
5. 写入审计日志。

### 7.3 组织联系名片

联系名片使用独立记录，不嵌入品牌 JSON。建议字段：

- `id`、`organization_id`；
- `display_name`、`title`；
- `phone`、`email`、`wechat` 中明确允许公开的子集；
- `status`：`active` 或 `disabled`；
- `created_by`、`updated_by`、时间戳。

公开 DTO 只返回创建分享时明确选择并写入快照的字段。

### 7.4 分享快照

在 `project_recording_share_boards` 上增加：

- `brand_snapshot jsonb`；
- `brand_version integer`；
- `contact_card_id uuid null`；
- `contact_card_snapshot jsonb null`。

创建分享时：

1. 读取组织当前发布品牌；
2. 读取并校验选中的活动联系名片，或确认“不展示”；
3. 将清洗后的公开字段写入快照；
4. 与分享项目、标题、用途、轮次、截止时间和录屏项一起提交；
5. 将品牌版本和名片选择写入审计日志。

已有分享在迁移时回填当时可获得的组织品牌字段。迁移完成后，公开读取只依赖分享快照，不实时读取组织当前品牌。

## 8. LOGO 存储与安全

图片 LOGO 复用现有私有存储基础设施，在组织路径下增加 `branding` 上传类别。上传规则：

- 支持 JPEG、PNG 和 WebP；
- 禁止 SVG，避免脚本和外部引用风险；
- 客户端裁切与压缩，服务端再次验证 MIME、扩展名、尺寸和体积；
- 建议原始上传上限 2 MB，规范输出不超过 512 × 512；
- 存储路径必须包含组织 ID，不接受客户端提供的任意路径；
- 公开分享通过已校验分享 token 的受控媒体路由读取，不直接暴露私有存储路径；
- 内部预览使用短时签名 URL；
- 删除旧 LOGO 前先确认没有品牌版本或活动分享仍引用该对象。

图片加载失败时回退到 `logoText`；`logoText` 缺失时从品牌名生成最多四个 Unicode 码点的字标。

## 9. 品牌色规则

品牌种子色只影响：

- LOGO 背景；
- 当前导航和选择状态；
- 主要操作按钮；
- 可见焦点；
- 公开分享抬头与待播放品牌封面。

品牌色不影响：

- 成功、预警、风险、错误和信息状态；
- 金额正负、差异和结算状态；
- 禁用、加载和不可用语义；
- 视频播放器原生控制状态。

品牌中心实时计算对比度。如果种子色无法让白色按钮文字达到要求，系统生成更深的操作色，并在预览中明确显示实际生效颜色。用户不直接覆盖系统生成的语义色。

## 10. 播放区域

### 10.1 待播放与加载

- 中间栏使用浅色中性媒体工作区，不把整栏设置为黑色；
- 视频画布保持真实宽高比并限制最大宽度；
- 待播放时展示品牌封面、主播名、项目名、轮次和播放按钮；
- 加载时在现有封面上叠加进度或骨架反馈，不隐藏整个内容；
- 品牌封面可以使用种子色生成，不依赖额外上传封面图。

### 10.2 正在播放

- 品牌封面淡出，真实视频接管画布；
- 横屏视频使用 16:9 画布；
- 竖屏或其他比例按比例居中，周围使用中性品牌底色，不补大面积纯黑背景；
- 播放器控件维持高对比、键盘可用和标准交互；
- 尊重 `prefers-reduced-motion`，封面切换可退化为即时切换或短交叉淡入。

### 10.3 失败状态

- 原始录屏失败：显示重试、报告问题和允许时的外部来源；
- 外部来源失败：显示安全的新窗口打开操作；
- 无可播放来源：保留录屏、主播和项目上下文，并给出明确恢复说明；
- 所有失败状态不得让复核草稿丢失。

## 11. 权限与隐私

### 11.1 品牌管理

- 仅 `owner` 可以新建草稿、编辑品牌、管理联系名片和发布；
- 其他组织成员只读当前已发布品牌；
- 所有发布、回滚、名片启停和紧急移除动作写入审计日志。

### 11.2 分享创建

- 保持现有项目与角色授权；
- 有分享创建权限的成员可以从活动联系名片中选择一张，或选择不展示；
- 不能输入自由联系人文本绕过组织名片治理；
- 不能选择其他组织的名片；
- 公开读取仍由分享 token、有效期、撤销状态和访问码会话共同保护。

### 11.3 联系名片停用

- 普通停用只阻止新分享继续选择该名片；
- 已有分享默认保留快照稳定性；
- 负责人可以执行“从所有有效分享中移除”，该动作批量清空活动分享的名片快照并写入审计；
- 已撤销或已过期分享无需修改。

## 12. API 契约

### 12.1 品牌中心 API

需要支持：

- 读取当前发布品牌、活动草稿、版本和联系名片；
- 创建或更新草稿，携带 `expectedVersion`；
- 上传 LOGO 并绑定到草稿；
- 发布草稿；
- 新建、更新、停用联系名片；
- 紧急从所有活动分享移除联系名片。

冲突返回明确的版本冲突错误，不静默覆盖其他负责人的修改。

### 12.2 分享创建 API

现有创建分享请求增加可空 `contactCardId`。品牌版本不由客户端提交，服务端始终读取当前发布品牌并生成快照。

### 12.3 公开分享 DTO

公开 DTO 增加：

```ts
type PublicShareBrandSnapshot = {
  logoText: string;
  logoUrl: string | null;
  brandName: string;
  brandTagline: string;
  primaryColor: string;
};

type PublicShareContactCard = {
  displayName: string;
  title: string;
  phone?: string;
  email?: string;
  wechat?: string;
};
```

`logoUrl` 是受分享 token 保护的应用路由，不是存储路径。未选择名片时 `contactCard` 必须为 `null`，不得返回空对象或组织默认个人信息。

## 13. 状态与降级

### 13.1 品牌中心

- 首次使用：从现有组织名称、字标、品牌名和副标生成起始草稿；
- 上传中：显示可取消进度，不提前改变线上品牌；
- 保存失败：保留本地草稿并提供重试；
- 版本冲突：展示线上新版本与当前草稿的差异，要求负责人重新确认；
- 发布失败：线上版本保持不变；
- LOGO 无效：阻止发布并给出格式、体积或尺寸原因；
- 品牌色无效：显示实际校正后的颜色或要求重新选择。

### 13.2 主界面和分享页

- 品牌数据缺失：使用组织名称、字标和经营舱默认中性色；
- LOGO 加载失败：回退字标，不显示破图；
- 联系名片为空：整块不渲染；
- 快照版本未知：忽略未知字段并使用安全默认值；
- 公开页面不因品牌资源失败而阻止录屏复核。

## 14. 响应式与可访问性

- 桌面公开复核页维持“录屏列表／媒体／复核意见”三栏；
- 中等视口允许复核意见移到媒体下方；
- 移动端录屏列表进入抽屉，媒体和意见纵向排列，上一条／下一条操作保持可达；
- 品牌中心在窄屏改为编辑区在上、预览区在下；
- 所有品牌编辑控件具备可见标签、错误说明和键盘操作；
- 颜色不是任何业务状态的唯一信号；
- 正文和控件满足 WCAG AA 对比度；
- 动效尊重减少动态效果偏好；
- LOGO 使用有意义的替代文本，纯装饰品牌封面不重复朗读；
- 异步保存、发布和播放错误使用礼貌状态播报。

## 15. 验收标准

### 15.1 品牌中心

- 负责人可以创建草稿、上传 LOGO、选择主色、编辑名称和口号、管理联系名片并发布；
- 非负责人不能写入或发布；
- 草稿不会在发布前影响其他成员和公开页面；
- 并发发布不会静默覆盖；
- 发布记录包含前后版本、发布者和变更字段。

### 15.2 内部工作台

- 发布后侧栏在下一次权威刷新时显示新 LOGO、品牌名、口号和操作色；
- 状态色不随品牌色改变；
- LOGO 失败时显示字标；
- 品牌中心入口和只读／编辑权限正确。

### 15.3 分享快照

- 新分享保存当前品牌版本和选中的联系名片快照；
- 修改组织品牌后，已有分享保持原快照；
- 新分享使用最新发布版本；
- 未选择名片时公开 DTO 不包含联系方式；
- 紧急移除可以从所有活动分享清除指定名片并留下审计记录。

### 15.4 内外一致

- 内部管理视图和公开页面的组织、项目、标题、用途、轮次、截止时间、录屏项和排序一致；
- 内部私有字段不会出现在公开 DTO、HTML 或浏览器网络响应中；
- 外部提交回执能在内部视图中查看。

### 15.5 媒体与浏览器验证

- 待播放和加载阶段显示品牌封面，不出现整栏纯黑块；
- 原始录屏、外部嵌入、外部链接、横屏、竖屏、加载失败和无来源状态均经过真实浏览器验证；
- 播放失败不会清空当前评审草稿；
- 桌面、窄屏和移动端不存在文字截断、控件遮挡或不可达操作。

## 16. 测试边界

实施至少需要覆盖：

- 品牌字段规范化、颜色派生和对比度单元测试；
- LOGO 文件类型、体积、路径隔离和授权测试；
- 品牌草稿、发布、版本冲突和审计 API 测试；
- 联系名片跨组织隔离、停用和紧急移除测试；
- 分享创建快照、已有分享稳定性和公开 DTO 泄漏测试；
- 主界面品牌回退组件测试；
- 公开录屏页同源字段与播放器状态组件测试；
- 键盘、焦点、ARIA 状态播报和减少动态效果测试；
- 真实浏览器下的原始视频和外部来源验证。

## 17. 发布与回滚

建议按以下产品边界逐步启用，但具体任务拆分由后续实施计划确定：

1. 数据结构、权限和品牌读取兼容；
2. 品牌中心与发布流程；
3. 主界面品牌层；
4. 分享创建快照与内部管理视图；
5. 公开录屏页品牌抬头和播放区域；
6. 浏览器验证与受控上线。

所有新增字段必须提供旧数据回退。若公开页面出现品牌或媒体回归，可以关闭新的公开品牌渲染，继续使用现有项目复核页面和原有录屏播放链路；品牌数据与分享快照保留，不执行破坏性回滚。

## 18. 设计结论

本方案不是简单给经营舱换一套主题，而是在现有多租户、项目、分享和审计边界之上增加一层稳定的组织身份：

- 内部成员看到自己的组织工作台；
- 外部接收者看到同源、受控、专业的项目分享；
- 经营舱继续提供能力、权限和安全，但不抢夺用户品牌的第一视线；
- 品牌变化可预览、可发布、可追溯，已有分享保持稳定；
- 任何品牌装修都不能牺牲业务状态、隐私、复核效率和媒体可用性。
