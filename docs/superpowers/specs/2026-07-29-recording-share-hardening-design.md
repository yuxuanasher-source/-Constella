# 录屏分享链路加固设计

## 背景与目标

当前 `/share/admission/[token]` 已能展示直接视频、平台嵌入和私有存储录屏，但审查确认存在四类上线风险：

1. 同一录屏同时有私有原始上传和外部链接时，公开 DTO 优先外链，导致权威原始证据不可见。
2. 访问码只能通过查询参数传递，创建接口返回的分享地址与公开页面输入流程不闭环，且访问码进入 URL、历史和日志。
3. 公开 DTO 返回复核人姓名和联系方式，异常响应也可能把底层技术错误直接暴露给访客。
4. 媒体失败、枚举中文化和移动端触控目标不够健壮。

本次目标是在不改变“项目优先、MCN 初审通过后分享、厂家人工复核、录屏版本锁定”业务边界的前提下，把分享路由修复为可恢复、可解释、证据源明确且隐私边界收紧的公开验收页面。

## 已批准的产品原则

- 私有原始上传是权威证据；外部链接是辅助来源。两者并存时优先播放原始上传，同时保留“在原平台打开”。
- 访问码不进入新生成的分享 URL。页面在需要时显示访问码表单，验证成功后使用受限的 HttpOnly Cookie 访问公开 API 和私有视频路由。
- 旧的 `?accessCode=` 链接只作为迁移入口：首次打开后换取 Cookie，并从地址栏移除访问码。
- 公开 DTO 使用显式字段白名单，不返回复核人姓名、联系方式、存储路径、token 摘要或组织内部标识。
- 公开 API 只返回稳定错误码和中文用户文案；底层异常留在服务端日志。
- 访问码采用带随机盐的 scrypt 摘要，新旧摘要双读兼容；访问码验证使用数据库原子限流。
- 失败的视频或平台嵌入必须给出可理解的回退说明，并保留可点击的原始来源。

## 架构

### 1. 公开录屏来源

`toPublicShareDto` 按以下顺序生成来源：

1. `storagePath` 存在：`playbackUrl` 指向受 token/Cookie 保护的公开播放路由，`hasPrivateStorage=true`。
2. 仅有 `externalUrl`：直接视频进入原生 `<video>`，支持的平台链接进入 `<iframe>`，其他链接显示外部来源卡片。
3. 两者都不存在：显示“暂无可播放录屏”。

`recordingUrl` 仅用于展示辅助外链，不决定权威播放源。

### 2. 访问码会话

新增 `POST /api/public/admission-share/[token]/access`：

1. 接收 JSON `{ accessCode }`。
2. 读取 token 对应的有效分享看板。
3. 使用数据库限流器检查客户端指纹是否被阻断。
4. 验证带盐摘要或兼容旧 SHA-256 摘要。
5. 成功后创建高熵、短期、服务端可撤销的访问会话，并把不透明会话 token 写入 `HttpOnly + SameSite=Lax + Secure(生产)` Cookie；Cookie 路径仅覆盖该 token 的公开 API。

公开看板、复核提交和录屏播放路由从 Cookie 读取访问码，不再要求查询参数。客户端遇到 `ACCESS_CODE_REQUIRED` 或 `ACCESS_CODE_INVALID` 时显示访问码表单。

### 3. 访问码存储与限流

- 新建访问码使用 `scrypt$<salt>$<digest>` 格式。
- 旧的 64 位 SHA-256 摘要继续可验证，避免现有分享链接失效。
- 新增 `project_recording_share_access_attempts` 表及安全定义函数，以“分享看板 + 哈希客户端指纹”为维度记录 15 分钟窗口内的失败次数。
- 新增 `project_recording_share_access_sessions` 表，只保存高熵会话 token 的 SHA-256 摘要和过期时间；Cookie 不保存原始访问码。
- 五次失败后阻断 15 分钟；成功验证会清空失败计数。
- 客户端指纹只存服务端 HMAC/SHA-256 结果，不存原始 IP。

### 4. 公开错误契约

公开 API 统一返回：

```json
{
  "code": "ACCESS_CODE_REQUIRED",
  "error": "请输入访问码后继续查看。"
}
```

错误码至少覆盖：

- `SHARE_NOT_AVAILABLE` — 404
- `SHARE_EXPIRED` — 410
- `ACCESS_CODE_REQUIRED` — 401
- `ACCESS_CODE_INVALID` — 401
- `ACCESS_RATE_LIMITED` — 429
- `RECORDING_NOT_SHARED` — 404
- `REVIEW_VALIDATION_FAILED` — 400
- `RECORDING_VERSION_STALE` — 409
- `SHARE_SERVICE_UNAVAILABLE` — 503

未知异常只记录服务端日志，访客统一看到“分享服务暂时不可用，请稍后重试”。

### 5. 页面交互与视觉

- 初始失败状态提供“重新加载”按钮。
- 访问码卡片包含明确标签、密码输入框、提交中状态和错误播报。
- 历史复核决策使用独立中文映射，`backup` 显示“备选”。
- 顶部显示“已判断 X / N”，底部操作栏在手机端使用紧凑摘要，减少遮挡。
- 原始链接、下拉框和主要按钮最小触控高度 44px。
- 视频失败后显示错误说明和“打开原始链接”；平台短链或不支持内嵌的格式明确提示在原平台查看。
- YouTube 增加 `/shorts/`、`/live/`、`/embed/` 格式解析；B 站短链保持安全外链回退，不伪造嵌入地址。

## 测试策略

所有行为按 RED → GREEN → REFACTOR 实施：

- 服务测试：双来源优先级、公开 DTO 白名单、带盐摘要与旧摘要兼容、过期时间和访问码长度。
- 路由测试：访问码 Cookie、错误码、限流、公开字段剥离、私有播放不再依赖查询参数。
- 客户端测试：访问码表单、旧链接迁移、重试、中文枚举、媒体失败回退、YouTube URL 变体、44px 控件类名。
- 数据库契约测试：限流表、原子函数、权限撤销和安全定义。
- 最终验证：聚焦测试、完整 `pnpm test`、`pnpm type-check`、`pnpm lint`、`pnpm build`、`git diff --check`，并在桌面与手机视口做真实浏览器回归。

## 非目标

- 不新增厂家账号体系。
- 不改变 MCN 初审、厂家复核和最终入项的状态机。
- 不自动同步金钱、结算或证据变更。
- 不尝试通过客户端跨域请求展开 `b23.tv`；短链使用明确的原平台回退。
