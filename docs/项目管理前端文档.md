# 项目管理 · 前端文档

> 适用代码库：`jingying-cabin`（经营舱 MCN 运营台）
> 范围：经营 Web 端「项目管理」模块的前端实现——渲染链路、数据流、数据契约、UI 结构、交互动作与 API 映射、扩展指引。
> 不含后端服务/数据库实现细节（见各 `features/projects/*` 与 `supabase/migrations/*`）。

---

## 1. 模块概览

「项目管理」是经营台的核心模块，承载项目的**创建 → 招募 → 执行 → 结算 → 归档**全生命周期。前端由两层组成：

- **服务端取数层**：Next.js Server Component `app/(ops)/console/projects/page.tsx`，在服务端并行拉取项目、协作、直播任务、结算等数据，转成 UI DTO 后作为 props 注入。
- **客户端渲染层**：单页参考 UI 巨型客户端组件 `components/reference-ui/ops-reference.jsx`（`"use client"`），通过内部「路由」状态切换屏幕，项目管理对应 `ScreenProjects`。

> ⚠️ 注意：参考 UI 是一个**单文件单页应用**（`OpsReferenceApp` 默认导出），内部用 `route` 状态切换屏幕，导航点击不是真实的 URL 跳转。真实数据通过 props 自服务端注入，再由 `useOps*` 系列 hook 在组件内消费。

## 2. 渲染链路

```
app/(ops)/console/projects/page.tsx   (Server Component, 取数)
        │  projectCards / collaborationProjectCards / liveTasks / liveBatches …(props)
        ▼
OpsReferenceApp  initialRoute="projects"        (components/reference-ui/ops-reference.jsx)
        │  route === "projects" | "project"
        ▼
ScreenProjects({ go, projectId })               (ops-reference.jsx:5117)
        ├─ projectId 为空 → ProjectList          (列表页, :5122)
        └─ projectId 有值 → ProjectDetail         (详情页)
```

- `ScreenProjects` 仅做分流：有 `projectId` 渲染 `ProjectDetail`，否则渲染 `ProjectList`。
- `go(route, params)` 是内部导航函数，用于在列表/详情/其他屏幕之间切换。

## 3. 数据流

### 3.1 服务端 → 客户端（props 注入）

`page.tsx` 中关键步骤（`app/(ops)/console/projects/page.tsx`）：

| 数据 | 服务端查询 | UI 适配器 | 注入 prop |
|---|---|---|---|
| 自有项目 | `listProjects(supabase)` | `toProjectCardDtos` | `projectCards` |
| 协作项目（合作方视角） | `listPartnerCollaborationProjects` | `toCollaborationProjectCardDtos` | `collaborationProjectCards` |
| 协作申请项目 | `listPartnerCollaborationApplications` | `toCollaborationApplicationProjectCardDtos` | `collaborationProjectCards` |
| 直播任务 | `listOpsLiveTaskQueue` | `toOpsReferenceTask` | `liveTasks` |
| 结算批次/明细/池 | `listOpsSettlement*` | `toOpsReferenceBatch*` | `liveBatches` 等 |

- 取数全部 `Promise.all` 并行。
- **容错降级**：合作方协作数据通过 service-role admin client 查询，若该 client 配置错误或查询失败，会 `catch` 后降级为空数组并 `console.error`，**不让单点失败 500 掉整个项目台**（见 `loadPartnerCollaborations`）。

### 3.2 客户端内消费（hooks）

`ProjectList` 通过 hook 读取注入的数据：

| Hook | 位置 | 返回 |
|---|---|---|
| `useOpsProjects()` | `ops-reference.jsx:1070` | 自有项目卡数组 |
| `useOpsCollaborationProjects()` | `:1075` | 协作项目卡数组 |
| `useOpsLiveActions()` | `:1178` | 写操作动作集合（见第 7 节） |

列表展示集合 = `[...projects, ...collaborationProjects]`（`ProjectList` :5230）。

## 5. 状态与展示映射

### 5.1 状态机（后端真值，前端只读展示）

定义于 `features/projects/project-state.ts`，8 个状态：

```
draft → recruiting → pending_start → active ⇄ paused → ended → settling → archived
```

合法流转：
- `draft` → `recruiting` / `archived`
- `recruiting` → `pending_start` / `active` / `paused` / `ended`
- `pending_start` → `active` / `paused` / `ended`
- `active` ⇄ `paused`，二者均可 → `ended`
- `ended` → `settling` / `archived`
- `settling` → `archived` / `ended`
- `archived` → （终态）

> 前端**不自行做状态流转校验**，发布走 `publishProject` 动作；非法流转由后端 `assertProjectTransition` 拦截并返回错误，前端展示报错文案。

### 5.2 中文标签映射（`statusLabels`，project-ui-dto.ts:3）

| status | 标签 |
|---|---|
| draft | 草稿 |
| recruiting | 招募中 |
| pending_start | 待开始 |
| active | 进行中 |
| settling | 结算中 |
| paused | 已暂停 |
| ended | 已结束 |
| archived | 已归档 |

### 5.3 状态徽章配色（`ops-reference.jsx:1014`）

| status | tone |
|---|---|
| recruiting | blue |
| active | green |
| paused | amber |
| ended | ink |
| settling | teal |

## 6. 项目列表 UI（`ProjectList`）

### 6.1 页头操作（`PageHeader`，:5266）

- **导出项目表**（`Icon.Export`）→ `exportProjectList()`，提交受治理导出；导出中按钮显示「导出中」并禁用。
- **新建项目**（`Icon.Plus`，primary）→ `openDraftForm()` 打开草稿表单。

### 6.2 状态筛选 Tabs（带计数，:5301）

`全部 / 进行中 / 招募中 / 结算中 / 已暂停 / 已结束`，每项实时显示计数 `counts.*`（`ProjectList` :5231 计算）。

### 6.3 工具栏筛选（:5319）

| 控件 | 状态变量 | 说明 |
|---|---|---|
| 搜索框 | `query` | 匹配 `name/code/id/vendor/product/leadOps/bizOwner`（小写包含） |
| 厂商筛选 | `vendorFilter` | 按 `vendor` 精确匹配 |
| 负责人筛选 | `ownerFilter` | 按 `leadOps` 精确匹配 |
| 时间范围筛选 | `scheduleFilter` | `scheduled`（有排期）/ `unscheduled`（无排期），由 `hasProjectSchedule(p)` 判定 |

### 6.4 客户端过滤逻辑（:5240）

`filtered = displayProjects.filter(...)`，对状态 / 搜索 / 厂商 / 负责人 / 排期五个条件求**与**。过滤纯前端进行，不触发新的网络请求。

### 6.5 新建项目表单（`draftOpen` 弹层）

两种模式（`draftMode`）：
- **owned（自有项目）**：填写 `项目名称` + `项目编号`（默认 `P-<时间戳>`）→ `submitProjectDraft()` → `createProjectDraft({name, code})`。
- **协作加入**：填写邀请链接 → `submitCollaborationInvite()` → `joinCollaborationProject({inviteLink, …})`。

表单含 `draftError` / `draftMessage` / `draftSubmitting` 三态反馈，提交成功后清空并关闭，失败展示后端错误文案。

## 7. 交互动作 → API 映射

动作集合定义于 `useOpsLiveActions()`（`ops-reference.jsx`），通过 `fetchJson` 调用后端，成功后调用对应 `refresh*` 重新拉取并刷新 UI：

| 动作 | HTTP | 端点 | 触发处 |
|---|---|---|---|
| `createProjectDraft(input)` | POST | `/api/projects` | 新建项目表单（:22738） |
| `publishProject(id)` | POST | `/api/projects/:id/publish` | 详情页发布（:22760） |
| `joinCollaborationProject(input)` | POST | `/api/collaboration-projects/join` | 协作加入表单（:22747） |
| `createGovernedExport(input)` | POST | 受治理导出 | 导出项目表（:23288） |

> 列表页只读 + 创建/导出/加入协作；项目级编辑（基础信息、结算规则、财务设置、成本项等）在 `ProjectDetail` 内调用 `/api/projects/:projectId/*` 系列端点。完整端点见 `app/api/projects/**`。

---

## 8. 项目详情页（`ProjectDetail`）

当 `go("project", { projectId })` 时由 `ScreenProjects` 分流渲染。详情页覆盖单项目的概览、主播、报数、结算、成本、设置等子视图，并对接 `/api/projects/:projectId/*`（结算规则、财务设置、成本项、成本导入、对账、协作份额、准入分享板等）。

---

## 9. 对外分享页（项目协作）

- 路由：`app/share/project-collaboration/[token]/page.tsx`
- 客户端：`project-collaboration-page-client.tsx`
- 用途：合作方凭 token 访问的**公开**项目协作页（独立于经营台外壳，不需要登录态进入参考 UI），用于查看/提交协作申请。

## 11. 前端扩展指引

- **加一列展示**：在 `ProjectCardDto`（project-ui-dto.ts）加字段并在 `toProjectCardDto` 填充 → 在 `ProjectList` 表格渲染处读取。务必让 DTO 转换层产出，**不要在 UI 里直接读原始 row**。
- **加一个状态筛选**：在 `ProjectList` 的 `Tabs.items` 加项，并在 `counts` 与 `filtered` 的 `matchesStatus` 中处理对应 `status`。
- **加一个写动作**：在 `useOpsLiveActions()` 内新增 `xxx: async (input) => fetchJson("/api/projects/...", ...)`，成功后 `await refreshProjects()`；UI 处通过 `useOpsLiveActions()` 取用并接管 loading/error 反馈。
- **新增独立真实页面**（不并入巨石单页）：可参考「账号库」的做法——独立 Server Component 路由 + 复用 `Sidebar`/`TopBar` 外壳（`components/account-library/account-library-shell.tsx`），保持视觉一致的同时使用真实服务端数据。
